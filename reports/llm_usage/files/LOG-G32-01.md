### 1. Keep UI logic separate from business logic
- **Structure:** UI layer (views) → controller/handlers → model (data/logic).
- **Why:** Easier testing, reuse, and maintenance.

### 2. Validate input early and clearly
- Validate on change and on submit.

### 3. Use native widgets where possible
- Native widgets give users familiar behavior (focus, keyboard navigation, accessibility).

### 4. Use asynchronous or background threads for long tasks
- Don’t block the GUI thread. Use threads, `QThread` (PyQt), or `after()` (Tkinter) to keep UI responsive.

### 5. Provide sensible defaults and input constraints
- Use input masks, dropdowns, date pickers, numeric spinners to reduce invalid input.

### 6. Accessibility and keyboard navigation
- Ensure tab order, labels, and keyboard shortcuts are set.

import re

### Key functions in the `re` module

| **Function** | **What it does** | **When to use** |
|---|---:|---|
| `re.search(pattern, string)` | Finds first location where pattern matches anywhere in string | Check if pattern appears anywhere |
| `re.match(pattern, string)` | Matches pattern only at the start of string | Pattern must begin the string |
| `re.fullmatch(pattern, string)` | Matches entire string to pattern | Validate whole string against pattern |
| `re.findall(pattern, string)` | Returns list of all non-overlapping matches | Extract all matches as strings |
| `re.finditer(pattern, string)` | Returns iterator of match objects | Iterate matches with positions |
| `re.sub(pattern, repl, string)` | Replace matches with `repl` | Perform substitutions |
| `re.compile(pattern, flags=0)` | Compile pattern to reuse efficiently | Reuse pattern many times; pass flags |

### Python equivalent of JavaScript `join`

**Short answer:** use **`str.join()`** in Python.

**Example (joining a list of strings with a comma):**

items = ['apple', 'banana', 'cherry']

### What it means
**`TypeError: 'str' object is not callable`** means your code tried to *call* (use parentheses like a function) a string value. In Python only callables (functions, methods, classes, objects with `__call__`) can be invoked with `(...)`. If a variable holds a string and you write `variable(...)`, Python raises this `TypeError`.

---

### Common causes (with short examples)

- **You used parentheses after a string literal or string variable**

s = "hello"
s()            # TypeError: 'str' object is not callable
"hi"("x")      # same error


- **You shadowed a built-in function or name with a string**

str = "oops"
str(123)       # TypeError because str is now a string, not the built-in function


- **You forgot to index or slice and used parentheses instead**

lst = ["a", "b"]
lst(0)         # TypeError; use lst[0] instead


- **You used `()` instead of `[]` for dict/list access**

d = {"k": "v"}
d("k")         # TypeError; use d["k"]


- **You assigned a string to a name that should be a function**

func = "not a function"
result = func()  # TypeError

---

### How to fix it
1. **Check the expression before `(...)`** — ensure it’s a function or callable, not a string.  
2. **Avoid shadowing built-ins** — don’t assign to names like `str`, `list`, `max`, etc. If you did, delete or rename the variable:
   ```python
   del str
   ```
3. **Use the correct operator** — use `[]` for indexing, not `()`.  
4. **If you intended a function, define or reference it properly**:
   ```python
   def greet(name): return "hi " + name
   greet("Sam")   # OK
   ```
5. **Add debugging prints** to inspect the type:
   ```python
   print(type(x), x)
   x()   # will fail if x is not callable
   ```

---

### Quick checklist to debug
- Is the name before `(...)` a string?  
- Did you accidentally assign a string to a function name (e.g., `str = "..."`)?  
- Should you be using `[]` or `.` instead of `()`?  
- Print `type(name)` to confirm.

If you paste the small snippet causing the error, I’ll point out the exact line and the minimal fix.

### Updating an object inside a function (Python 3)

**Short answer:**  
- If the object is **mutable** (e.g., `list`, `dict`, most user-defined objects), modify it *in place* inside the function and the caller sees the change.  
- If the object is **immutable** (e.g., `int`, `str`, `tuple`), you cannot change it in place; return a new value and assign it to the caller’s variable.

---

### Key concepts

- **Mutability matters.** Mutable objects can be changed in place; immutable objects cannot.
- **Names (variables) are references.** When you pass a variable to a function, Python passes a reference to the object. Rebinding the parameter name inside the function does not rebind the caller’s name.
- **Two common patterns:** modify in place, or return a new object.

---

### Examples

#### 1) Modify a mutable object in place (caller sees changes)

def append_item(lst, item):
    lst.append(item)

my_list = [1, 2]
append_item(my_list, 3)
print(my_list)  # [1, 2, 3]


#### 2) Rebind inside function — does NOT affect caller

def reassign_list(lst):
    lst = [9, 9]   # rebinds local name only

a = [1, 2]
reassign_list(a)
print(a)  # [1, 2]


#### 3) Return a new value for immutable objects (caller must assign)

def add_one(n):
    return n + 1

x = 5
x = add_one(x)
print(x)  # 6


#### 4) Update attributes of a user-defined object (in place)

class Counter:
    def __init__(self, value=0):
        self.value = value

def increment(c):
    c.value += 1

c = Counter()
increment(c)
print(c.value)  # 1


#### 5) If you want to replace the caller’s reference with a new object
Return the new object and assign it in the caller:

def replace_dict(d):
    d = {'new': True}   # local rebind
    return d

orig = {'a': 1}
orig = replace_dict(orig)
print(orig)  # {'new': True}
